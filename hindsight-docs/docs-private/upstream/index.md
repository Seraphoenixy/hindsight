## 分支与远程约定

- `main` 保持与上游一致，`private` 承载个人定制。
- 本机无需创建或检出 `main`。目前 `origin` 指向个人仓库，`origin/main` 是评估上游输入的引用。
- 远程跟踪引用会移动，完整 SHA 固定不变；每轮记录评估前后的 SHA，不能只记分支名或日期。

## 下一轮同步步骤

1. 检查工作区、暂存区和现有同步记录，确认尚未提交的改动。
2. 获取 `origin/main`，无需切换工作目录；如果 clone 只跟踪 private，显式获取 main 引用。
3. 从当前评估边界到最新引用列出新增提交，同时重新检查此前暂缓的功能。
4. 按[裁剪边界](../maintenance/trimming.md)筛选，逐项决定引入、部分移植、暂缓或跳过，并写明原因。
5. 按上游顺序移植；保留本地配置默认值、原生推理与 Magpie 生命周期，检查同一文件的前置依赖。
6. 运行受影响部分的测试和必要 lint；只在用户要求时执行全量测试。
7. 创建新的日期批次记录，更新本页的评估边界和暂缓项；核对代码与记录一起进入提交。

获取与比较示例：

```bash
git status --short
git fetch --filter=blob:none origin refs/heads/main:refs/remotes/origin/main
git log --reverse --oneline 00c9d19e2d9386a54d84a9a12b9fc385df7009e1..origin/main
git show <待评估提交>
```

## 批次记录要求

每个批次独立存为 `YYYY-MM-DD.md`；同日多轮增加主题后缀。记录上游基准、评估终点、每个提交的完整 SHA、处理方式与原因、路径过滤、本地适配和实际验证结果。

历史批次保留当时结果；下一轮只更新本页入口与新批次，不覆盖旧清单。提交、推送状态以 Git 实际状态为准，文档不充当暂存区状态标记。
