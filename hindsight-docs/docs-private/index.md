# Private 分支维护入口

本目录记录基于 Hindsight 的个人定制、实现边界与上游同步状态。`main` 跟随上游，`private` 维护本地使用体验、Magpie 管理入口和运行依赖裁剪。

## 按任务查找

| 要做的事 | 入口 |
| --- | --- |
| 判断 private 对应哪个上游版本 | [上游同步状态与流程](upstream/index.md) |
| 查看已引入、暂缓和跳过的具体提交 | [2026-11-24 同步批次](upstream/2026-11-24.md)、[2026-11-23 同步批次](upstream/2026-11-23.md) |

| 排查 Magpie 加载和进程问题 | [本地管理排障](maintenance/local-management.md) |

## 给接手的 AI 或维护者

1. 先读上游同步状态，再读最近的同步批次；评估边界不代表所有上游提交都已引入。
2. 以运行架构了解现状，再按问题查看单项 ADR；历史记录中退役的 DSH 界面不能作为现行设计。
3. 修改之前检查 `git status`，保留既有暂存和未暂存内容。文档中的同步记录不代表 Git 提交已创建或推送。
4. 验证遵循当前用户要求：运行受影响部分的测试及必要 lint，不默认执行全量测试。

## 文档分类约定

- `architecture/`：当前架构和每项独立 ADR；ADR 保留决策日期、背景、取舍及替代关系。
- `upstream/`：同步策略、当前评估边界和按日期保存的批次清单。
- `maintenance/`：裁剪范围、平台限制和可重复使用的排障步骤。

新增同步批次后更新 `upstream/index.md`。实现变化时更新当前架构；新增或替代设计选择时再新增 ADR。批次验证结果放在批次文档，避免把决策文件当作工作日志。
